# my-angular-project-front 药品管理系统前端项目介绍文档

## 1. 项目概述

本项目是基于需求文档《工作簿1.xlsx》开发的**药品管理系统**前端工程，实现以下三大画面：

| 画面 | 说明 |
| ---- | ---- |
| 简单 login 画面 | 用户名 + 密码登录，成功后进入药品检索页面 |
| 药品检索页面 | 按药品名称检索列表，支持新增/编辑/删除，低库存购买提示 |
| 新增（编辑）药品 POP 画面 | 新增与编辑共用同一弹窗画面，确定后刷新列表，取消则数据废弃 |

配套文档（`docs/` 目录）：

- `docs/数据库建表SQL.txt` —— MySQL 建表与初始数据 SQL
- `docs/API接口文档.txt` —— 前后端 API 约定（供后端开发使用）

## 2. 技术栈与环境适配

| 项目 | 版本 | 说明 |
| ---- | ---- | ---- |
| Node.js | v10.24.1（本机已装） | 因此选择 Angular 11（要求 Node ≥10.13） |
| npm | 6.14.12 | 随 Node 10 附带 |
| Angular | 11.2.x | 框架 |
| TypeScript | 4.1.x | 语言 |
| RxJS | 6.6.x | 异步/数据流 |
| Angular Router | 11.x | 路由 |
| Angular HttpClient + FormsModule | 11.x | HTTP 请求 / 模板驱动表单 |

## 4. 功能实现说明

### 4.1 登录画面（/login）
- 用户名、密码两个输入框 + 登录按钮，回车也可提交。
- 调用 `AuthService.login()`（虚拟 URL：`POST {apiBaseUrl}/auth/login`）。
- Mock 模式账号：`admin / 123456`；登录信息存 `sessionStorage`，未登录访问列表页会自动跳回登录页。

### 4.2 药品检索画面（/medicines）
- **检索**：按药品名称模糊查询（`GET /medicines?medicineName=xxx`），支持回车检索与重置。
- **欢迎语**：`XXX 先生/女士，以下是您的药品列表。`（XXX 为登录用户姓名）。
- **列表**：No / 药品名称 / 生产厂家 / 生产日期 / 保质期 / 失效日期 / 剩余数量（盒）/ 单盒药品数量（片）/ 吃药时间区分 / 每日吃药次数 / 每次吃药数量（片）/ 备注注意事项 / 编辑 / 删除。
  - 保质期在库中以“月”存储，画面按“年”显示；
  - 失效日期由**生产日期 + 保质期**计算（后端持久化返回，前端展示）；
  - 失效日期距今 ≤90 天时橙色高亮；
  - 剩余数量 ≤1 盒时红色高亮。
- **新增药品**按钮：打开新增 POP；**编辑**按钮：打开编辑 POP（回填数据）；**删除**按钮：`confirm` 确认后调用删除接口并从列表移除。
- **低库存提示**：列表下方提示剩余 ≤1 盒、需要购买的药品名称清单。

### 4.3 新增（编辑）药品 POP 画面
- 新增/编辑共用一个弹窗组件 `app-medicine-form-modal`。
- 表单项：药品名称*、生产厂家、生产日期*、保质期（月）*、失效日期（只读，**实时自动计算**）、新增数量（盒）*、单盒药品数量（片）*、吃药时间区分*（下拉，取自码表接口）、每日吃药次数*、每次吃药数量（片）*、备注注意事项。
- 必填校验，错误信息红色提示；【确定】提交后关闭弹窗并刷新列表，【取消】直接关闭、数据废弃。
- 编辑时“新增数量”为累加到剩余数量的增量。

### 4.4 失效日期计算规则
`失效日期 = 生产日期 + 保质期(月)`，见 `medicine.service.ts` 的 `calcExpiryDate()`。
例：2026-01-01 + 24 个月 = 2028-01-01。前后端需保持同一算法（后端持久化返回，前端 POP 实时预览）。

## 5. API 调用与虚拟 URL

所有 HTTP 调用集中在 `src/app/services/`，URL 前缀统一取自 `environment.apiBaseUrl`（当前为虚拟地址 `http://localhost:8080/api`）：

| 功能 | 方法 | 虚拟 URL |
| ---- | ---- | ---- |
| 登录 | POST | `/auth/login` |
| 药品检索 | GET | `/medicines?medicineName=` |
| 新增药品 | POST | `/medicines` |
| 编辑药品 | PUT | `/medicines/{medicineId}` |
| 删除药品 | DELETE | `/medicines/{medicineId}` |
| 吃药时间码表 | GET | `/codes/intake-time` |

**Mock 机制**：`environment.useMock = true` 时不发真实请求，由 `mock-db.ts` 提供与文档示例一致的演示数据；后端就绪后：
1. 将 `apiBaseUrl` 改为真实地址；
2. 将 `useMock` 改为 `false`；
3. （可选）删除 `mock-db.ts` 及各 service 中的 mock 分支。

**数据结构**：全部定义于 `src/app/models/api.models.ts`（`Medicine`、`MedicineSaveRequest`、`LoginRequest`、`LoginResult`、`CodeItem`、`ApiResponse<T>`、`MedicineListResult`），与 `docs/API接口文档.txt`、数据库表字段一一对应，已绑定到各画面。

## 6. 数据库设计概要

详见 `docs/数据库建表SQL.txt`：

- `user_mst` 用户表（user_id 主键）
- `medicine` 药品表（user_id + medicine_id 联合主键，expiry_date 为计算冗余列）
- `code_mst` 区分码表（吃药时间区分：001 餐前 / 002 随餐 / 003 餐后）
